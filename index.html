      How We Evaluate & Compare Models

      Our methodology for selecting and recommending LLMs

      Model Inclusion Criteria

      Models are included in our catalog if they meet ALL of the following:

      • API Available — Must have programmatic API access (not just chat interfaces)
      • Production Ready — Generally available or in public preview (not private beta)
      • Enterprise Viable — Suitable for commercial/industry use
      • Active Support — Not deprecated or scheduled for imminent shutdown

      Benchmark Selection

      Not all benchmarks are equal. We prioritize benchmarks that:

      Task Alignment

      Benchmark tests what users actually do (e.g., SWE-bench tests real GitHub issues)

      Difficulty Spread

      Differentiates between models (GPQA ranges 60-95%, not 95-99%)

      Recency

      Recent benchmarks are less likely contaminated in training data

      Industry Adoption

      Used by multiple providers/researchers (SWE-bench cited by Anthropic, OpenAI, Google)

      Use CasePrimary BenchmarkWhy This Benchmark
      CodingSWE-bench Verified/ProTests actual bug fixes in real repos
      ReasoningGPQA DiamondPhD-level science requires deep reasoning
      MathAIME 2024/2025Competition problems resist memorization
      GeneralChatbot Arena ELOBlind human preference voting, millions of comparisons

      Conversation Quality

      We assess "natural conversation" through multiple signals:

      • Chatbot Arena ELO — Blind human preference voting with millions of comparisons
      • Context awareness — References earlier conversation naturally
      • Tone matching — Adapts formality to user's style
      • Graceful ambiguity handling — Asks clarifying questions when needed
      • Appropriate uncertainty — Admits when it doesn't know something

      Coding Ability

      SWE-bench is our primary coding benchmark because it tests end-to-end software engineering: reading code, understanding bugs, and writing fixes that pass real test suites.

      BenchmarkWhat It TestsScore Range
      SWE-bench Verified2,294 easier GitHub issues50-80%
      SWE-bench Pro500 harder issues30-65%
      HumanEvalBasic code generation75-95%

      Context window matters for coding: large codebases need 200K-1M+ tokens to process effectively.

      Cost Effectiveness

      We calculate a value index comparing quality to price:

      $ (Low Cost)

      <$1/M input tokens — DeepSeek, Gemini Flash, Claude Haiku

      $$ (Mid Range)

      $1-5/M input — GPT-5.1, Gemini Pro, Claude Sonnet

      $$$ (Premium)

      >$5/M input — Claude Opus, GPT-5.2 Pro, o3

      Self-Hosted

      No per-token cost — Llama, Qwen, Mistral (requires GPU infrastructure)

      Privacy & Self-Hosting

      For data-sensitive applications, we evaluate models across three tiers:

      • Self-Hosted — Full control, data never leaves your servers (Llama, Qwen, Mistral)
      • Private Cloud — Vendor-managed but isolated (Azure OpenAI, Bedrock, Vertex AI)
      • Standard API — Data sent to provider's shared infrastructure

      Data Sources

      We verify information from multiple sources with this priority:

      • Official documentation — Provider API docs and pricing pages
      • Published papers — ArXiv papers and technical reports
      • GitHub repositories — Open-source model repos for technical specs
      • Independent benchmarks — Artificial Analysis, LMArena, SWE-bench leaderboards
